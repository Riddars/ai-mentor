## Правила общего сервера

Инструкция кластера — `github.com/ai-chem/server_manual` (проверено 2026-10-22). Она написана для
расчётов, о постоянных сервисах в ней ничего нет; держать куратор на `serveritmo` разрешил Николай
(2026-10-19). Что из неё и из договорённостей касается нас:

- **Доступ** выдают Юлия Разливина или Ася Орлова — с согласия гайда и после теста; вход только по
  SSH-ключу, пароля и sudo нет. Всё, что требует sudo (Apache, сертификат, системные службы,
  linger), — просьбой к Николаю.
- **Расчёты** по правилам идут на ноде `aichem` через SLURM, не на общих машинах. Куратор
  тяжёлого не считает (модель — у Selectel), на `serveritmo` — только сам сервис; ничего
  вычислительного сюда не добавлять, видеокарты не занимать.
- **Чужое не трогать**: на машине работают сайты и контейнеры других проектов центра — не
  останавливать чужие процессы, не менять общие настройки, порты брать только согласованные (наш
  — 3100).
- **Место**: `/nfs/home/<user>` — 30 ГБ, `/mnt/tank/scratch/<user>` — 250 ГБ, оба на NFS; наш
  сервис живёт в `/home/asarkisyan` (локальный диск, выдан Николаем). Журнал `curator.log` растёт —
  при обновлении смотреть размер и обрезать.
- **Секреты** (`.env.local`, `app.pem`) — только с правами 600, в чаты и репозиторий не попадают.

## Как устроено

- **Прокси** — Apache на машине (настраивал Николай): сайты `curator.conf` и `curator-le-ssl.conf`
  ведут `curator.aicidlab.itmo.ru` на `127.0.0.1:3100` с `ProxyPreserveHost On`; с порта 80 —
  переадресация на HTTPS. Сертификат Let's Encrypt (certbot), продление — на стороне Николая.
- **Сервис** — `next start` на `127.0.0.1:3100` в сессии `tmux` `curator`, под пользователем
  `asarkisyan`. sudo нет.
- **Node.js 24** — через nvm в `/home/asarkisyan/.nvm`.

Папки — на локальном диске (`/home/asarkisyan` выдал Николай). Домашняя папка по умолчанию
(`/nfs/home/asarkisyan`) — на NFS, SQLite там ненадёжна; ничего из сервиса туда не класть.

| Путь | Что |
|---|---|
| `/home/asarkisyan/ai-curator/app` | клон `Riddars/ai-mentor`, сборка; настройки — `app/.env.local` (600) |
| `/home/asarkisyan/ai-curator/data/curator.db` | база (начата пустой 2026-10-22) |

Копии репозиториев для агента — в `/tmp` (локальный диск, очищается при перезагрузке — так и нужно).

Настройки — как в `развёртывание с нуля.md`, 4.3, кроме путей: ключ и база — по таблице выше; smee,
`CURATOR_SIM_*`, `SIM_ADMIN_TOKEN`, `ALLOW_DEV_SEED` не заданы; режим разбора — по умолчанию
(агентный). `TOKENS_PER_PROJECT_DAY=1500000` (с 2026-10-27; по умолчанию 1 млн): первый PR с кодом
до 600 тысяч плюс обзор после слияния с запасом 600 тысяч не помещались в миллион за сутки.

## Команды

```bash
# состояние и журнал
tmux ls
tail -f /home/asarkisyan/ai-curator/curator.log
curl -s http://127.0.0.1:3100/api/health

# остановить / запустить
tmux kill-session -t curator
tmux new-session -d -s curator /home/asarkisyan/ai-curator/run.sh
```

Обновление (сервис на время сборки останавливается; пропущенное за простой подхватит сверка с
GitHub при старте):

```bash
export NVM_DIR=/home/asarkisyan/.nvm; . $NVM_DIR/nvm.sh
cd /home/asarkisyan/ai-curator/app
git pull --ff-only
tmux kill-session -t curator
node -e "new (require('node:sqlite').DatabaseSync)('../data/curator.db').exec(\"VACUUM INTO '../data/curator-$(date +%F-%H%M).db'\")"
npm ci && npm run build
tmux new-session -d -s curator /home/asarkisyan/ai-curator/run.sh
curl -s http://127.0.0.1:3100/api/health
```

Если сборка не прошла — `git checkout <прежний коммит>`, снова `npm ci && npm run build`, запуск.

## Чего нет

- **Автозапуска после перезагрузки сервера** — отложено (2026-10-22). Пока сервер не
  перезагружался, хватает `tmux`; после перезагрузки сервис надо запустить вручную, иначе новые PR
  не сливаются (проверка `AI Curator` обязательная). Чтобы включить, нужна одна команда от
  Николая — `sudo loginctl enable-linger asarkisyan`, затем пользовательская служба systemd
  (`systemctl --user`) вместо `tmux`.
- **Сторожа `/api/health` с перезапуском** (`deploy/health-check.sh`) — рассчитан на системную
  службу; появится вместе с автозапуском.
- **Копий базы по расписанию** — только ручная копия при обновлении.
