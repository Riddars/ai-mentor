# Поиск проблем существующего проекта

## Статус поиска — уточнение 2026-11-23

По решению пользователя завершённый поиск показывает только подтверждённые замечания:
«Поиск завершён: новых подтверждённых замечаний N». Неподтверждённые кандидаты,
неопределённость при их сравнении и штатное исключение CSV/других данных сохраняются
во внутренней диагностике и не делают весь поиск частичным. Реальный сбой обработки,
лимит, оборванный ответ или незавершённая передача материалов по-прежнему означают
«Поиск не завершён»; их нельзя скрывать успешным статусом.

Старые завершённые project_audit с прежним сообщением «Поиск с ограничениями…»
отображаются по новой политике без изменения исторических записей и без новых
модельных вызовов. Обычные обзоры/PR и неизвестные технические partial-результаты
не переклассифицируются. Регрессии — test:project-audit.


Обновлено: 2026-11-23. Реализация `e729c80` влита в main, опубликована на GitHub и развёрнута на ИТМО по поручению пользователя. `PROJECT_AUDIT_ENABLED=true`. Живой платный разбор оставлен для ручной проверки пользователем.

После успешной initial/manual карты в parts-режиме в той же транзакции сохраняется неизменяемая карта с SHA, текстом и манифестом выбранных файлов; при включённом флаге ставится один дочерний поиск. Карта и публикация её issue остаются отдельными от поиска.

Поиск повторно получает исходники закреплённого SHA и сверяет их манифест с картой. Передаются карта, заметки, RESEARCH/PLAN и полная история project/main-находок, включая снятые/закрытые/ожидающие. Большая история получает индекс и обязательную полную пакетную сверку после поиска; отсутствие помещающегося индекса отмечается явно. Данные и notebook преобразуются общей политикой.

Кандидаты сохраняются по частям в SQLite. Независимая проверка путей/строк и модельная проверка исходных доказательств предшествуют сравнению по причине и месту с полной историей и уже принятыми кандидатами. Человеческое снятие не переоткрывается; доказанная регрессия закрытой проблемы создаёт новую запись со ссылкой на старую. Перед атомарным применением повторно сверяются история, заметки и SHA. Старые статусы не изменяются; новые записи имеют scope=project.

Новый kind `project_audit` явно проходит через worker, бюджет, повтор и завершение. Сбой сохраняет причину; завершённые части не отправляются заново. Поиск не создаёт issue/check/comment GitHub. SQLite24 добавляет project_maps и project_audit_runs с уникальной автоматической связью и каскадной очисткой. Расход отражается отдельно на странице «Расход».

Панель показывает карту и поиск отдельно. Кнопка «Проверить проект на ошибки» защищена проверкой руководителя/head, проверяет актуальность карты и активность проекта. Старые проекты массово не запускаются. Флаг PROJECT_AUDIT_ENABLED выключен по умолчанию. Модельные провайдеры и PR-режим сохранены.
