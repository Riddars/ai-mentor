# Приёмка ревью pull request

Обновлено: 2026-11-09.

## Без GitHub и расходов на модель

Выполнить `npm run test:reviews` и `npm run test:review-migration` (`test:private-pr` сохранён как прежнее имя). Тест использует временную базу, поддельный ключ
GitHub App и ответы модели. Он проверяет публичный и приватный репозитории,
уведомления о начале разбора, повторные события, слияние до ревью, ответ на
комментарий студента после слияния, восстановление пропущенного PR и очередь.
Дополнительно проверяются пять исходных дефектов, параллельные вебхуки, отказ финального GET
с учётом расхода, доставка сохранённого ответа после нового коммита и закрытия PR, проверка
файлов результата слияния, отдельный повтор PATCH и восстановление публикаций v17/v18.
Миграционный тест обновляет отдельные временные базы v17/v18 до v19 с сохранением строк.

## Проверка в GitHub

1. Создать небольшой репозиторий из шаблона в организации, выбрать любую
   видимость и подключить его в разделе «Управление». Проверить доступ приложения
   GitHub и приглашение участника с правом записи.
2. Открыть PR с очевидной ошибкой. В PR должен появиться один короткий комментарий
   о начале проверки. Повторная доставка события или новый коммит не должны
   дублировать его. Проверка `AI Curator` показывает ход разбора, но не должна быть
   обязательной для слияния.
3. Слить PR до окончания разбора. Итоговое ревью должно появиться в этом уже
   слитом PR; замечания должны отображаться в панели проекта.
4. В новом открытом PR дождаться замечания, затем написать комментарий студента.
   Куратор должен один раз подтвердить получение комментария. Слить PR до ответа.
   Ответ куратора должен появиться в том же слитом PR. Повторная доставка
   комментария не должна создавать второй ответ.
5. Для публичного проекта со старым ruleset проверить предупреждение в управлении.
   Убрать из действующего правила требование обязательного статуса `AI Curator`
   и обновить страницу: предупреждение должно исчезнуть. Остальные правила
   репозитория можно сохранить.

Первый обзор, ревью PR и повторный разбор комментария используют токены модели.
