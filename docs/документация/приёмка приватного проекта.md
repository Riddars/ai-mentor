# Приёмка приватного проекта

## Локальная проверка

С установленными зависимостями проекта выполнить `npm run test:private-pr`. Тест использует временную базу и тестовый ключ. Все HTTP-запросы обрабатываются внутри теста. Запускать сервис, заводить аккаунт GitHub и оплачивать ответы модели для этой проверки не требуется.

Тест вызывает обработчик подписанных событий GitHub и выполняет разбор через рабочую очередь. Проверяются комментарий в нужном PR, SHA разбора, состояние замечания в базе и список неудачных разборов для панели. Отдельно проверяются повторная доставка, опоздавшее событие открытия, слияние до и после ревью, обновление коммита, закрытие без слияния, восстановление пропущенного PR, повтор после ошибки и очередь обзоров. Для публичного проекта проверяется чтение обязательного правила ветки.

## Проверка на GitHub и сервере

1. Развернуть проверяемую версию. Создать маленький приватный репозиторий в организации проектов. Дать GitHub App доступ к нему. Для автора PR подойдёт существующая учётная запись участника с правом записи.
2. Добавить README и подключить репозиторий в панели. Проверить, что панель видит приложение, первый обзор запускается, а настройка обязательной проверки для этого режима не требуется.
3. Создать ветку и PR с небольшим примером ошибки, например с обучением модели на тестовых данных. Слить PR в основную ветку, пока разбор ещё идёт. Записать номер PR и SHA последнего коммита ветки PR.
4. Открыть слитый PR. Проверить, что появился один комментарий куратора. В панели открыть разбор того же SHA. Если модель нашла ошибку, замечание должно быть открыто в проекте и ссылаться на этот PR. Если модель не нашла ошибку, это отдельный результат проверки качества модели. Учёт замечаний воспроизводимо проверяется локальным тестом.
5. В публичном тестовом проекте с действующим правилом ветки открыть PR и проверить, что GitHub удерживает слияние, пока обязательная проверка выполняется.

На рабочей конфигурации внешний провайдер учитывает токены первого обзора, ревью и возможного обзора после слияния. Для проверки кнопки повтора, порядка событий и пропущенных уведомлений достаточно локального теста.
