# Языковая модель

Обновлено: 2026-09-27. Пометки — см. `00 обзор.md`. Код: `lib/llm/chat.ts`.

## Что известно и что нет

Известно:

- модель вызывается только нашим сервисом, один запрос на разбор, ответ целиком (без
  потоковой передачи) **[есть]**;
- модель **ничего не хранит между запросами** — вся память в нашей базе; при смене модели
  или провайдера память проекта сохраняется **[есть]**;
- провайдер не зафиксирован; сейчас provod.ai (OpenAI-совместимый шлюз), модель
  `deepseek/deepseek-v4-pro` **[есть]**;
- ограничений на передачу данных проекта во внешний API нет (см. `принятые решения.md`).

Неизвестно (решать не сейчас):

- облачный API или модель, развёрнутая локально (на сервере университета);
- будет ли у модели или сервиса доступ в интернет;
- будет ли модель мультимодальной (понимать картинки);
- какой будет бюджет и конкретная модель.

Поэтому решено требование: система работает **в минимальной конфигурации** — текстовая
модель без интернета, доступная по HTTP, с окном от 32 тысяч токенов. Всё, что требует большего, — отдельные возможности, которые
включаются, если модель их поддерживает.

## Требования к модели (минимальная конфигурация)

1. **Контекст не меньше ~32 тысяч токенов.** Один только diff при полном лимите — порядка
   15–20 тысяч токенов; к нему добавляются `RESEARCH.md`, открытые замечания проекта и ответы
   студента, которые **не ограничены** (см. `04 куратор изнутри.md`), плюс ответ. Модели с
   окном 8–16 тысяч (многие небольшие локальные) будут падать. Нужны лимиты на каждый блок
   запроса, настраиваемые под окно модели **[нет]**.
2. **Надёжный JSON.** Ответ разбирается как JSON; не получилось — один повторный запрос,
   затем `parse_error`: студенту — «разбор не удался», сырой ответ — только в панели, память
   не обновляется **[есть]**. Режим структурированного вывода (JSON mode /
   schema), который есть у многих провайдеров и локальных серверов, не используется **[нет]**
   — стоит включать, где поддерживается.
3. **Русский язык** — все тексты замечаний на русском.
4. **Знание предметной области** — химия, ML, типичные методические ошибки. Слабая модель
   даст больше ложных и пропущенных замечаний и хуже решит, исправлено ли замечание.
5. **Ответ за разумное время.** Тайм-аут запроса — 5 минут (`LLM_TIMEOUT_MS`); дольше —
   разбор считается неудавшимся **[есть]**.

Параметры запроса (`lib/llm/chat.ts`) **[есть]**:

- **`max_tokens`** — 8000 по умолчанию (`LLM_MAX_TOKENS`); ответ, обрезанный по лимиту
  (`finish_reason = length`), считается ошибкой, а не мусором.
- **Температура** — 0.2 по умолчанию (`LLM_TEMPERATURE`): низкая, чтобы модель меньше
  переформулировала те же проблемы и не «прыгала» статусами.
- **Кто ответил** — в разборе записываются фактические провайдер и модель, в том числе
  резервные.

Ещё не сделано: режим структурированного вывода **[нет]**. Рассуждающие модели выдают перед
JSON текст рассуждений, иногда с фигурными скобками; JSON ищется «от первой `{` до последней
`}`», и такой ответ разбирается с ошибкой **[есть]** — частично спасает один повторный
запрос.

## Без интернета

Разбор PR интернет **не требует** — всё нужное приходит в запросе **[есть]**. Сервису нужен
доступ к GitHub (получать события и файлы, публиковать комментарии) и к модели.

Без интернета не работает только **поиск научных публикаций** для ежемесячного обзора
(концепция, раздел 5). Решено: **поиск делает сервис** через бесплатные API научных баз
(OpenAlex, Semantic Scholar) и передаёт найденное модели — модели интернет не нужен, работает
и с локальной; детали — на этапе 4 **[нет]**. Отвергнуты: модель с инструментом поиска
(зависит от провайдера) и поиск без баз, по знаниям модели (риск выдуманных ссылок).

## Без мультимодальности

Сейчас модель получает только текст **[есть]**, и это работает в любом варианте. Что
теряется без картинок:

- графики и рисунки в ноутбуках и отчётах (кривые обучения, распределения) — модель их не
  видит;
- структуры молекул картинками.

Отдельная проблема — **ноутбуки `.ipynb`**: в diff попадает JSON ноутбука вместе с выводами
ячеек, включая картинки в base64. Это бессмысленно для текстовой модели и быстро съедает
лимит в 50 000 символов **[нет]** обработки. Нужно перед отправкой вырезать из ноутбуков
выводы и картинки и оставлять код и markdown-ячейки. Решено: картинки модели не передавать,
даже если она мультимодальная.

## Как сравнивать модели

Выбор модели сейчас не на чем обосновать: нет набора эталонных случаев **[нет]**.
Предложение: собрать набор тестовых PR с известными ошибками (утечка, дубликаты, метрика,
логическая ошибка, частичное исправление, правдоподобное, но ложное объяснение студента) и
прогонять на нём каждую модель-кандидата. Этот же набор — основа симуляции репозиториев
(см. `07 нештатные ситуации.md`).

## Стоимость

Одно событие (коммит в PR или комментарий студента) — один запрос с полным контекстом
**[есть]**. Много мелких коммитов подряд = много полных запросов. Оценка $100–250 в месяц
на 30 проектов из концепции (раздел 9) — предварительная гипотеза и считалась на тарифах
Anthropic; для provod.ai и локальной модели не пересчитывалась. Решено пересчитать по факту
после первого месяца реальной работы, а не заранее.
Экономия, если понадобится: откладывать разбор на короткое время после коммита и разбирать
только последний (**[нет]**).
