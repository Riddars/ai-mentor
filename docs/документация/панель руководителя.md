# Панель руководителя (этап 5)

Обновлено: 2026-09-10.

Рабочий документ по пятому этапу — веб-панели наблюдения за проектами. Ведётся по ходу
реализации: что сделано, как запускать, какие решения приняты и что осталось. Читать вместе
с разделом 7 `детализированная концепция.md` (он описывает замысел панели) и
`принятые решения.md`.

## Назначение

Панель — часть того же приложения на Next.js. Она даёт руководителям читаемую картину по
проектам, которую собрал куратор (память этапа 3). Панель ничего не анализирует сама: она
только показывает накопленные данные (проекты, участники, pull request, находки, статусы,
активность) и позволяет управлять подключением проектов и учётными записями.

## Роли

Две роли. Студенты панелью не пользуются — они работают через GitHub.

- **`head` — главный руководитель центра.** Видит все проекты, сводную картину, управляет
  учётными записями и подключением репозиториев. Единственная роль с доступом к `/admin`.
- **`supervisor` — руководитель проекта.** Видит только назначенные ему проекты и их
  детализацию. Управления учётками и подключением у него нет.

## Вход и учётные записи

Механика входа повторяет проверенный образец: подписанный токен (HMAC по `AUTH_SECRET`) в
httpOnly-cookie.

- `lib/auth.ts` — только криптография токена и тип `Viewer`. Edge-безопасен (работает в
  `proxy.ts`), без доступа к диску.
- `lib/users.ts` — хранилище пользователей в SQLite, пароли только хэшем (PBKDF2-SHA256),
  `getViewer()` для страниц и server actions.
- `proxy.ts` — единственные ворота: запрос без валидного токена уходит на `/login`
  (API получает 401), раздел `/admin` — только для `head`.
- **Bootstrap.** Если таблица пользователей пуста, при первом входе создаётся `head` из
  переменных `HEAD_LOGIN` / `HEAD_PASSWORD`. Пароли пользователей не связаны с `AUTH_SECRET`.
- **Фейл-закрыто.** Без `AUTH_SECRET` в production сервис закрыт; в разработке открыт.

Учётки руководителей проектов заводит `head` в `/admin`: создаёт запись, назначает ей
проекты, может отключить. Студенческих учёток в панели нет.

## Управление проектами

В `/admin` руководитель центра:

- **подключает** новый репозиторий (добавляет проект по `owner/repo`);
- **ставит на паузу** (`status = paused`) — проект остаётся в системе, но помечен
  приостановленным;
- **архивирует** (`status = archived`) — убирает из активного списка;
- назначает проекту руководителя.

Проект со статусом `active` — в работе. Настройку защиты ветки в GitHub панель пока не
трогает (это делает этап 1 при создании репозитория); здесь — только учёт состояния.

## Уровни информации (раздел 7 концепции)

1. **Общий список проектов** (`/`) — таблица: название, участники, этап/активность, открытые
   серьёзные замечания, статус внимания с причиной. `head` видит все, `supervisor` — свои.
2. **Страница проекта** (`/projects/[id]`) — цель и этап, активность, открытые и закрытые
   находки, последние прогоны разбора.
3. **Досье проблемы** (`/projects/[id]/findings/[fid]`) — описание, место, подтверждение,
   влияние, рекомендация, ответ студента, история смены статуса.

## Статус внимания

Статус вычисляется из фактов и **всегда сопровождается причиной** (текстом). Пороги — это
предварительная гипотеза (раздел 7 прямо помечает их как гипотезу), вынесены в константы и
будут уточняться на реальных данных.

- `red` (требует внимания): открытая серьёзная находка (severity high/critical) старше 14
  дней **или** нет активности более 30 дней.
- `yellow` (стоит посмотреть): есть открытые находки **или** активности нет 14–30 дней.
- `green` (в норме): иначе.

Цвет дублируется текстом причины, чтобы не опираться только на цвет.

## Стек и стиль

- Next.js 16 (App Router, server components, server actions), TypeScript, Tailwind CSS 4.
- В Next.js 16 middleware переименован в **`proxy`** (`proxy.ts` в корне) — это не прежний
  middleware по имени.
- UI — свои лёгкие примитивы в `components/ui/` (`cn`-хелпер, без shadcn CLI, без cva и
  base-ui): проще и меньше зависимостей. Токены темы — oklch, светлая и тёмная.
- Шрифт Inter из `@fontsource-variable/inter` (локально, без обращения к Google Fonts — важно
  для сервера без внешнего доступа).
- Данные — тот же SQLite (`lib/db`, `lib/curator/store.ts`). Весь SQL — только в этих двух
  файлах.
- Комментарии и идентификаторы — на английском, кратко и по делу.

## Модель данных (добавления к этапу 3)

- `users` — id, login, password_salt, password_hash (PBKDF2), role, name, created_at,
  disabled.
- `project_supervisors` — связь проект ↔ руководитель (many-to-many).
- `projects.status` — `active` | `paused` | `archived`. Заменил булев флаг `connected` из
  схемы этапа 3 (тот нигде не читался); `connected` удалён миграцией (user_version 3).

## Как запускать

1. В `.env.local` задать как минимум:
   - `AUTH_SECRET` — любая длинная случайная строка (подпись токенов);
   - `HEAD_LOGIN`, `HEAD_PASSWORD` — учётка главного руководителя (bootstrap при пустой базе);
   - при необходимости `DATABASE_PATH` (по умолчанию `./data/curator.db`).
   Полный GitHub-конфиг для работы панели не нужен.
2. `npm run dev`.
3. Залить демо-данные (только для разработки): открыть/запросить `POST /api/dev/seed`
   (эндпоинт включён при `ALLOW_DEV_SEED=1` или в dev). Он создаёт демо-проекты, находки и
   учётку руководителя проекта.
4. Войти на `/login`.

Демо-учётки после сидирования (dev): `head` / `head` (или из env) и `supervisor1` /
`supervisor1` (назначен на часть проектов).

## Состояние

**Версия очень сырая — каркас для обсуждения, а не готовый интерфейс.** Функционально сквозной
путь работает (роли, список, проект, досье, управление), но внешний вид далёк от желаемого и
будет дорабатываться итерационно. Направления доработки — в разделе «Что осталось / дальше».

Первый прототип проверен локально (dev + production-сборка). Реализовано:

- Вход и роли: `lib/auth.ts` (токен), `lib/users.ts` (пользователи в SQLite, PBKDF2),
  `proxy.ts` (ворота, `/admin` только для `head`), `app/actions/auth.ts` (вход/выход),
  `components/LoginForm.tsx`, `app/login/page.tsx`.
- Общий список проектов `app/page.tsx` — таблица со статусом внимания, причиной,
  участниками, счётчиком замечаний и активностью; `head` видит все, `supervisor` — свои.
- Страница проекта `app/projects/[id]/page.tsx` — открытые и закрытые находки, участники,
  последние разборы.
- Досье проблемы `app/projects/[id]/findings/[fid]/page.tsx` — все поля находки, ответ
  студента, история статуса.
- Управление `app/admin/page.tsx` + `app/actions/admin.ts` — подключение репозитория,
  смена статуса (active/paused/archived), назначение руководителя, создание и отключение
  учёток руководителей.
- Статус внимания `lib/attention.ts`; форматирование `lib/format.ts`; UI-примитивы
  `components/ui/`.
- Демо-данные `lib/dev/seed.ts` + `app/api/dev/seed` (owner `demo-org`, идемпотентно).

Что проверено вживую (локально):

- Production-сборка (`next build`) проходит: типы, границы server/client, server actions.
- Ворота: запрос без cookie → редирект на `/login`, API → 401; подделанный токен отклонён.
- Изоляция ролей: `supervisor1` видит только свои 2 проекта, не видит пункт «Управление»,
  получает 404 на чужой проект и редирект с `/admin`; `head` видит все 5 проектов и `/admin`.
- Пароли: round-trip PBKDF2 (верный пароль принят, неверный отклонён).
- Статус внимания: red (серьёзное замечание открыто 20 дн.), yellow (нет активности 18 дн.),
  green, плюс проект на паузе — отображаются с причинами.

Замечания по итогам теста: пока нет. Открытые вопросы дизайна и функционала — за
пользователем после просмотра.

## Что осталось / дальше

Дизайн прототипа — рабочий минимум. Приоритет следующих итераций — сделать панель
по-настоящему удобной и приятной глазу. Направления (со слов пользователя после просмотра
первой версии):

- **Общий вид и дизайн.** Первая версия выглядит сыро и далека от желаемого; переработать
  визуальный язык, графические элементы, сделать таблицы удобнее и красивее. Рассмотреть
  готовые UI-библиотеки для дизайна (например, полноценный shadcn/ui, как в референсе, либо
  иной набор компонентов) вместо текущих самодельных примитивов.
- **Главные страницы.** Экраны списка проектов (и у руководителя центра, и у руководителя
  проекта) переработать — сейчас они не такие, как хочется.
- **Отображение кода.** Удобный вывод фрагментов кода с подсветкой (Shiki, раздел 8),
  примеры, выделение конкретных строк в досье находки.
- **Инфографика и блоки.** Графики активности (Recharts, раздел 8), визуальные блоки,
  наглядные индикаторы вместо простых бейджей.
- **Markdown в досье** — текст находок и обзоров выводить как Markdown, а не как простой текст.

Отдельно (из концепции, раздел 7), пока не начато:

- Регулярная сводка руководителю (раз в две недели); способ доставки в концепции не выбран.
- Представление проектов карточками в дополнение к таблице («может быть»).
