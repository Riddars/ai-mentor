## Этап 1

Новые модули: `context-size.ts`, `context-parts.ts`, `repository-inventory.ts`.
Манифест/представления на диске, UTF-8 диапазоны, детерминированный упаковщик,
проверка покрытия, повторное построение допущенного запроса по хешу.
Счётчик по умолчанию — оценка, не настоящий токенизатор модели; замена
счётчика предусмотрена интерфейсом и не меняет алгоритм упаковки.
Формат PR diff адаптируется отдельно на этапе 3; здесь проверяется общий
механизм и обычное текстовое представление. Существующий runtime не переключён.

Проверено: `npx tsx scripts/context-parts-selftest.mts` (49 частей, 40 Unicode
fixtures, побайтовое восстановление, BOM/CRLF/emoji, отсутствие потерь,
проверка подмены контекста, файловый манифест); TypeScript; целевой ESLint.

## Этап 2

`INITIAL_OVERVIEW_MODE=parts` включает новый путь; прежний режим пока остаётся
по умолчанию. Миграция SQLite22 сохраняет ответы частей. Большая карта
объединяется иерархически, формат проверяется, исправление JSON ограничено.
Политика исключения вынесена в независимый модуль. Данные передаются только
в виде формата/размера; `.env.example` — только имена настроек без значений.

Первое ревью судьи выявило ошибки стабильности ключа при retry, допуска
полностью сохранённого результата с малым остатком бюджета, размера
промежуточных описаний и окна резервной модели. Добавлены исправления и
регрессионные проверки: `map-pipeline-selftest.mts`, `map-queue-selftest.mts`.
Последний проверяет настоящий executeOverviewJob и SQLite с заглушенными
GitHub/LLM: прерывание, повтор, изменение режима/ручных notes между попытками.
Завершённая часть не отправляется повторно, ручные заметки сохраняются.
Счёт за все эти проверки — ноль: сеть заменена заглушками.

Дополнительные проверки второго gate: восстановление перепланированного
исследования с остатком 65000 (одна часть + сборка), перепланированного reducer
с остатком 50000 (одна часть + сборка), полностью сохранённого результата
с остатком 100 (ноль вызовов). План бюджета учитывает максимальные разрешённые
размеры будущих описаний и все уровни сборки; 10 файлов по 140000 символов
при недостаточном бюджете останавливаются ДО вызовов модели.
Судья самостоятельно повторил четыре suite `test:context` и TypeScript.

## Этапы 3–4

Полный Git diff по закреплённым base/merge-base/head; более 300 файлов,
переименования, удаления, изменения типа/режима, submodules и огромные строки.
В отдельном Pi runtime разрешён только read_file целого файла с проверкой окна.
Сведение использует все части, включая не нашедшие ошибок. Новые замечания
проверяются по исходным материалам; противоположные вердикты — по общим
доказательствам. Прежние замечания проверяются группами; ручное снятие защищено.

Судья выявил и проверил исправления: один огромный файл требует такого же
ограничения описаний, как несколько файлов; готовый Pi-ответ восстанавливается
до допуска бюджета даже при остановке перед записью результата части;
разрешённая позднее неопределённость не блокирует итог навсегда. Итоговый
complete-результат восстанавливается с остатком100 токенов без вызовов модели.
`npm run test:pr-context`, TypeScript, целевой ESLint — успешно. Судья отдельно
повторил suite и TypeScript. Настоящие модель/GitHub публикации не вызывались.

## Этап 5

`REVIEW_MODE=context` подключает новый PR-процесс к прежней очереди/outbox.
В SQLite23 сохраняются история Pi, результаты частей, деревья перепаковки,
причины ожидания и общий расход. Перед отправкой фиксируется начало запроса.
Неизвестный расход учитывается один раз; известный HTTP-отказ без генерации
не превращается в оплаченный расход. Дневное ожидание не сбрасывает общий cap.
Суточный допуск проверяется перед каждым запросом, без резерва950k на маленькийPR.

Временная ошибка проверки/дневного бюджета оставляет задание для автоповтора;
нехватка общего бюджета или неверные настройки — ожидание изменения конфигурации.
Готовый результат допускает только бесплатное восстановление даже при дневном
лимите; изменение base/head проверяется непосредственно перед фиксацией.
Сохранённая публикация повторяет только доставку. Новых студенческих кнопок нет.
Слияние в промежуточную ветку и поздний разбор слитогоPR сохраняют прежнюю логику.

Судья дал PASS после независимых проверок. `test:context-recovery` покрывает
меньшее окно fallback, восстановление части после сбоя, максимум2 исправления
формата между рестартами, учёт неизвестных запросов/суточных лимитов, outbox,
ошибку транзакции между analysis и diagnostics, смену base и cascade очистки.
