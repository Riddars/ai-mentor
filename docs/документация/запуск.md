# Запуск

Обновлено: 2026-10-12.

Как поднять сервис локально и принимать события GitHub. Постоянного развёртывания пока нет:
сервис работает на компьютере, события GitHub доходят до него через канал smee.io.

## Что нужно

- Node.js 24 (база — встроенный `node:sqlite`), `npm install` в корне репозитория.
- GitHub App организации `RiddarsCorp`: ID, закрытый ключ `.pem`, секрет вебхука. В настройках
  приложения (вкладка General) **Webhook URL** — канал smee `https://smee.io/WVSknT6PNVXhHNbj`.
  Адрес постоянный, при каждом запуске менять его не нужно.
- `.env.local` — копия `.env.local.example` с заполненными значениями (файл не коммитится).
  Главное:
  - `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY_PATH`, `GITHUB_WEBHOOK_SECRET`;
  - `CURATOR_REVIEWER`: `simulate` — заглушка без модели (бесплатно, режим — `CURATOR_SIM_MODE`),
    `llm` — разбор моделью;
  - модель: `LLM_PROVIDER=selectel`, `LLM_MODEL=deepseek/deepseek-v4-pro`, `LLM_REASONING=off`,
    ключ `SELECTEL_API_KEY`;
  - `REVIEW_MODE`: `diff` (по умолчанию) — один запрос по изменениям PR, `agent` — агент читает
    копию репозитория; лимиты агента — `AGENT_*`;
  - панель: `AUTH_SECRET`, `HEAD_LOGIN`, `HEAD_PASSWORD`;
  - `SMEE_URL` — адрес канала smee;
  - `HEARTBEAT_URL` — адрес сигнала «жив» для внешнего монитора (см. «Оповещение о сбоях»).

## Запуск

Два окна PowerShell в корне репозитория.

1. Сервис:
   ```
   npm run dev
   ```
   Проверка: http://localhost:3000/api/health. База `data/curator.db` создаётся и обновляется
   сама.
2. Пересылка событий из канала smee в сервис:
   ```
   npx smee-client --url https://smee.io/WVSknT6PNVXhHNbj --target http://localhost:3000/api/github/webhook
   ```

Оба окна держать открытыми, пока нужны разборы. События, пришедшие, пока клиент smee не был
запущен, не доставляются: такой PR нужно обновить новым коммитом.

Панель руководителя — http://localhost:3000, вход `HEAD_LOGIN` / `HEAD_PASSWORD` (при пустой базе
учётная запись создаётся при первом входе). Репозиторий разбирается, только если он подключён
как проект: «Управление» → проекты. Участники проекта собираются из авторов PR.

Сборка как в рабочем режиме: `npm run build`, затем `npm run start` (без `CURATOR_REVIEWER`
сервер не запустится).

## Оповещение о сбоях

Пока разборы идут моделью (`CURATOR_REVIEWER=llm`), обработчик очереди раз в 5 минут
отправляет GET-запрос на `HEARTBEAT_URL`, если всё в порядке. Сигнал не отправляется, если
есть задачи в повторах после ошибки, окончательные неудачи или проверки «не разобрано» за
последний час (причина — в журнале сервиса, строка `heartbeat withheld`); упавший или
зависший сервис тоже молчит. Монитор поднимает тревогу по тишине.

Подойдёт любой сервис heartbeat-мониторинга, принимающий запрос на уникальный адрес. Выбран
CronBox (cronbox.ru): российский; бесплатный тариф — до 2 heartbeat-мониторов, интервал не
меньше 15 минут, оповещения на почту, Telegram — через своего бота (по тарифам на 2026-10-12).
Healthchecks.io из России не открылся. Настройка: heartbeat-монитор с интервалом 15 минут
(сервис шлёт сигнал чаще — это допустимо), оповещение на почту; адрес монитора — в
`HEARTBEAT_URL` в `.env.local`. Сбой замечается за 15–30 минут. Адрес не коммитить: по нему любой может слать сигналы.

## Репозитории для проверки

- `RiddarsCorp/test` — подключён как проект; на нём проверяется агентный разбор.
- `RiddarsCorp/test-project-1`, `test-project-2` — ранние проверки этапов 1–3.
- `RiddarsCorp/project-template` — шаблон репозитория студента.

В `main` этих репозиториев действует защита: изменения — только через PR с обязательной
проверкой `AI Curator`. Значит, PR можно слить, только когда сервис запущен и проверка
завершилась.

## Проверки без GitHub

```
npx tsc --noEmit
npm run lint
npx tsx scripts/agent-selftest.mts                       # агент, бесплатно
npx tsx --env-file=.env.local scripts/bench.mts --dry     # тестовый набор без модели
```

Платный прогон тестового набора — см. «Где остановились» в `агентный разбор — план.md`.
