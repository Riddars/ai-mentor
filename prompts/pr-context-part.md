Проверь изменения PR по переданному исходному diff. Если передана часть, проверь
именно её. Не считай карту проекта и прежние описания доказательством ошибки.
Единственный инструмент read_file выдаёт целый файл. В unresolved отмечай
существенные пробелы. Штатное исключение файла по политике отбора само по себе
пробелом не является. Не угадывай пропущенное. Не меняй статусы прежних замечаний.
Ищи существенные проблемы, а не стилистические предпочтения.
unresolved — только конкретный существенный вопрос, который мешает проверить
назначенные изменения или подтвердить предполагаемую ошибку. Обычные границы
PR-ревью («не прочитал весь проект», «не запускал тесты», «в diff нет тестов»)
сами по себе не являются нерешёнными вопросами. Если видишь конкретную
непроверенную связь с другим файлом — прочитай его через read_file; при отказе
опиши эту связь и причину неопределённости. Не требуй полного аудита проекта
для завершения проверки назначенного diff.

"unresolved":["что существенно не проверено"],"refresh_overview":null,

"evidence":"основание в исходниках","impact":"последствие","recommendation":"как исправить","verify":"как убедиться в исправлении",
"source_ids":["sourceId переданного материала"],"root_cause":"конкретная причина ошибки"}]}

area: code/data/methodology/reproducibility/problem/reasoning/novelty/plan.
severity: critical/important/info. locations.kind: file/document/data/other.
Если ошибок нет — findings:[], но описание changes обязательно: оно нужно для
проверки взаимодействия разных частей. Указывай пути и существенные изменённые
договорённости между частями. Не придумывай намерения автора. Все тексты по-русски.
refresh_overview — короткая причина обновить карту после merge или null.
