Как писать. Пиши простым техническим языком.
В description сначала объясни концепцию: какой принцип нарушен и почему это ошибка в общем случае
(одно предложение). Затем детали: как это сделано в этом проекте — файлы, функции, переменные, что
именно происходит (1-2 предложения).

Образец того, как написать находку (это пример стиля, а не содержания — не ищи эту ошибку
специально):
  title: "Гиперпараметры подобраны по тестовой выборке"
  description: "Тестовая выборка должна оставаться нетронутой до финальной оценки: если по ней выбирать параметры, она перестаёт быть независимой. Здесь max_depth перебирается в цикле, лучшее значение выбирается по r2_score на X_test, y_test, и этот же тест затем даёт итоговую метрику."
  evidence: "best = max(depths, key=lambda d: r2_score(y_test, fit(d).predict(X_test)))"
  impact: "Итоговый R² на тесте завышен и не отражает качество модели на новых данных."
  recommendation: "Подбирать max_depth кросс-валидацией на обучающей части (например, GridSearchCV), а тест использовать один раз — для итоговой оценки."
  verify: "max_depth выбирается без участия X_test и y_test."

Отвечай СТРОГО одним JSON-объектом, без текста вокруг и без Markdown-ограждения:
{
  "summary": "1-2 предложения: что проверено и главный вывод; находки не перечисляй — их список строится автоматически; без id находок",
  "findings": [
    {
      "prior_id": <id прошлой находки или null для новой>,
      "status": "open" | "closed" | "dismissed" | "reopened",
      "area": "code" | "data" | "methodology" | "reproducibility" | "problem" | "reasoning" | "novelty" | "plan",
      "severity": "critical" | "important" | "info",
      "title": "суть проблемы одной фразой техническим языком, без кода (до 90 знаков)",
      "description": "что не так: сначала концепция — какой принцип нарушен (одно предложение), затем как это сделано в этом проекте (1-2 предложения)",
      "locations": [
        { "kind": "file" | "document" | "data" | "other", "target": "путь, название документа или краткое описание", "detail": "строки, раздел или null" }
      ],
      "verify": "одно предложение: что должно быть в коде или документе, чтобы проблема считалась исправленной",
      "evidence": "1-3 строки точного кода или текста из файла, которые показывают проблему, без пояснений",
      "impact": "одно предложение: чем это грозит результатам или выводам",
      "recommendation": "1-2 конкретных шага: что изменить",
      "reason": "почему выбран этот статус или null"
    }
  ],
  {{tail}}
}
Все текстовые поля — на русском. Если существенных проблем нет — верни пустой массив findings, а в summary одним-двумя
предложениями напиши, что проверено и что проблем не найдено.
